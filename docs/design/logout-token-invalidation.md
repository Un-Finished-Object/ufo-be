# 로그아웃 시 발급 토큰 무효화

[#150](https://github.com/Un-Finished-Object/ufo-be/issues/150)에 따라 로그인별 상태를 MySQL에 저장한다. 로그아웃하면 해당 로그인에서 발급한 토큰은 더 이상 사용할 수 없다. 기존 DB를 사용하므로 별도 저장소 없이 여러 서버에서 같은 상태를 확인한다.

## 로그인 상태

- OAuth 로그인마다 `sid`를 만들고 Refresh Token과 재발급하는 Access Token에 같은 값을 넣는다. 같은 사용자의 다른 로그인은 별도로 관리한다.
- `auth_sessions`에 사용자, Refresh Token 만료 시각, 보관 종료 시각과 무효화 시각을 저장한다. 보관 종료 시각은 Refresh Token의 만료 시각과 마지막으로 발급한 Access Token의 만료 시각 중 더 늦은 시각으로 정한다.
- 토큰 원문은 저장하거나 로그에 남기지 않는다. 보관 기간이 지난 로그인 기록과 구형 토큰 해시는 기본 1시간 간격으로 삭제한다.

## 로그아웃과 인증

- 로그아웃 요청에 포함된 Access Token에 연결된 로그인을 무효화한다. 같은 사용자의 Refresh Token 쿠키가 있으면 해당 토큰에 연결된 로그인도 무효화한다. 요청에 포함되지 않은 다른 로그인에는 영향을 주지 않는다.
- 유효하지 않은 쿠키는 무시한다. 무효화 상태를 커밋한 뒤 쿠키 만료 응답을 보내며, DB 저장에 실패하면 로그아웃 성공으로 응답하지 않는다.
- 재발급과 로그아웃을 처리할 때는 사용자 행을 먼저 잠근 뒤 로그인 행을 잠근다. 격리 수준은 `READ_COMMITTED`를 사용한다. 인증 상태는 업무 트랜잭션의 이전 스냅샷에 영향을 받지 않도록 별도 트랜잭션에서 조회한다.
- REST와 STOMP는 JWT 검증 후 로그인 상태를 확인한다. `sid`에 해당하는 로그인 기록이 없거나 이미 무효화된 경우 인증을 거부한다. DB 조회 실패 시에도 인증을 허용하지 않는다.
- STOMP 연결 후에도 메시지를 보내거나 받기 전에 로그인 상태를 확인한다. 로그인이 무효화되거나 토큰이 만료되면 연결을 종료한다. 유휴 연결은 기본 30초 간격으로 확인한다. 로그아웃이 커밋된 뒤 검사하는 프레임부터 처리를 거부하며, 이미 전송한 메시지는 회수하지 않는다.

## 기존 토큰 처리

- `sid`가 없는 Refresh Token은 토큰의 SHA-256 해시를 로그인 식별자로 사용한다. 처음 토큰을 재발급하거나 로그아웃할 때 로그인 기록을 만든다. 이후 발급하는 Access Token에는 이 식별자를 넣는다.
- `sid`가 없는 Access Token으로 로그아웃하면 토큰의 해시와 만료 시각을 `revoked_access_tokens`에 저장한다. 이후 같은 토큰은 인증에 사용할 수 없다. 로그아웃 요청에 포함되지 않은 다른 구형 Access Token은 어느 로그인에 속하는지 알 수 없어 원래 만료 시각까지 유효하다.
- 값이 같은 구형 Refresh Token으로는 각 로그인을 구분할 수 없다.

## DB 변경

Flyway V4로 `auth_sessions`, `revoked_access_tokens`와 만료된 기록을 조회할 인덱스를 추가한다. 이전 애플리케이션으로 롤백하면 토큰 무효화 상태를 검사하지 않는다. 적용과 복구 절차는 [스키마 마이그레이션 안내](../database/schema-migrations.md)를 따른다.
